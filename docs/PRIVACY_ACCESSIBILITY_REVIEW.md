# MultiMini privacy, consumer and accessibility review

Reviewed November 6, 2026 for the local Windows facelift preview. Publisher location confirmed by the user: Ontario, Canada. This is an implementation review and a list of unresolved release questions, not a legal opinion or a guarantee against claims. No GitHub release was published.

## Changes made

Settings now includes Help with a guide and offline Privacy, Terms, Cookies, Refunds and Licenses pages. Corrected contradictory private-beta/manual-update statements: the app checks public GitHub releases on launch, with user confirmation before download/install. New agreement version requires renewed local acceptance. No marketing consent is bundled into that acceptance.

Added stronger control boundaries and keyboard focus cues, accessible names for source tools and form controls, and keyboard access to the accent selector. Contrast tests cover built-in dark/light palettes and all eight preset accent choices. These tests do not certify every custom color, screen, OS scale factor or assistive technology combination.

## Data and third-party audit

Reviewed Java UI/backend sources, Python frame transport/service, update script, package metadata and branding generator. No account, payment, support-submission form, analytics SDK, advertising tracker, browser cookie store, remote font or web/video embed was found in the app sources. Source names and configuration fields write local workspace/settings data. No new data collection was added. There are no app reviews/testimonials to remove.

External update traffic goes to GitHub's public Releases API and release download hosts; normal IP/request metadata reaches those services. User-opened GitHub pages and captured websites follow their own policies. Workspace window titles and paths, temporary frame files, screenshots, clipboard history/sync and public support submissions can disclose personal information. Policies describe these boundaries and local deletion options.

Assessment: no in-app cookie banner or support-form checkbox is warranted for this implementation. Reassess before adding webviews, tracking, marketing forms, accounts or payments. Canadian guidance requires appropriate meaningful consent for personal-information processing; a policy alone is not enough. [OPC consent guidance](https://www.priv.gc.ca/en/privacy-topics/privacy-for-businesses/appropriate-handling-of-personal-information/collecting-personal-information-and-consent/consent/gl_omc_201805/), [OPC cookie guidance](https://www.priv.gc.ca/en/privacy-topics/technology/online-privacy-tracking-cookies/cookies/frequently-asked-questions-about-cookies/).

## Ontario and Canadian requirements to resolve

- PIPEDA applicability depends on commercial activities and actual information handling, including support. Other provinces and countries can impose additional obligations when serving their residents; Ontario location alone does not settle jurisdiction. No conclusion of exemption was made. [OPC overview](https://www.priv.gc.ca/en/privacy-topics/privacy-laws-in-canada/the-personal-information-protection-and-electronic-documents-act-pipeda/pipeda_brief/).
- Confirm whether distribution is entirely free, whether there are paid services or donations, the legal seller identity, and a business mailing address. Before a paid offer, supply applicable seller/contact, price, delivery, cancellation and refund disclosures. The current Refund Policy describes the absence of an in-app payment flow and preserves mandatory rights; it does not invent a refund deadline or a blanket no-refunds clause. Ontario's e-Laws search listing showed the Consumer Protection Act, 2023 not yet in force at review; recheck commencement and applicable regulations before selling. Direct e-Laws fetch was blocked, so this is not a completed statutory analysis. [Ontario online-purchase guidance](https://www.ontario.ca/page/safe-online-shopping), [Consumer Protection Act, 2002](https://www.ontario.ca/laws/statute/02c30), [Consumer Protection Act, 2023](https://www.ontario.ca/laws/statute/23c23).
- Establish a confidential privacy contact, an access/correction/deletion request process, support retention rules and incident response before soliciting sensitive reports. The existing GitHub Issues channel is public; no private email or mailing address was invented. PIPEDA safeguards and breach obligations, if applicable, need an operational process beyond policy text.
- Ontario's AODA public-website rules depend on organization type and employee count; they are not automatically a desktop-app certification. Other accessibility duties may still apply. Use WCAG contrast thresholds as engineering targets and arrange manual Windows screen-reader/keyboard testing. [Ontario accessibility guidance](https://www.ontario.ca/page/how-make-websites-accessible), [W3C text contrast](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum), [W3C control contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Copyright, licensing and remaining technical risks

Branding is generated from the bundled publisher-supplied logo; toolbar icons are code-drawn. No stock images or fake endorsements were added. Logo provenance cannot be proven from the repository: retain the original creation record or license. User-captured content may require permission, and capture compatibility is not permission to bypass protections or game rules. [Canadian copyright guidance](https://www.ised-isde.canada.ca/site/ised/en/about-copyright).

The preview retains Java module notices, Python's license and package .dist-info license files. Packages include Pillow, mss, platformdirs, windows-capture, NumPy and OpenCV; their transitive notices also matter. Review Java redistribution terms for the actual bundled runtime (the inspected build JDK includes Oracle No-Fee Terms and Conditions, now copied as runtime/JDK-LICENSE.txt) and component redistribution obligations before publishing. Metadata presence alone does not prove license compliance.

Local frame transport binds to 127.0.0.1 and shared mappings use random names, but loopback frame requests are not authenticated; other local processes may access frames if they discover source identifiers. No security fix to capture transport is included in this UI/policy revision. Temporary captures after crashes, clipboard copies and backups also remain risks. The Windows app is unsigned; update checksums detect corruption but do not independently authenticate a compromised release account.

The composition canvas, source-row mouse toggles, drag/resize gestures and screenshot region selection still need a dedicated accessibility review. Added names describe controls and documents; they do not generate alt text for private captured pixels or establish full screen-reader support. No automated image descriptions or uploads were introduced. No full WCAG, AODA, privacy or legal compliance claim is made.
